bz supports configuration via TOML files for persistent settings. This is useful for setting default behaviors, especially for air-gapped environments.

## Configuration Files

bz reads up to three TOML files. Each one is optional.

| Layer | Linux and macOS | Windows |
|-------|-----------------|---------|
| System | `/etc/bz/config.toml` | `%ProgramData%\bz\config.toml` |
| User | `$XDG_CONFIG_HOME/bz/config.toml` if `XDG_CONFIG_HOME` is set, else `~/.config/bz/config.toml` (also on macOS) | `$XDG_CONFIG_HOME\bz\config.toml` if set, else `%AppData%\bz\config.toml` |
| Project | `.bz.toml` (or `.bzconfig.toml`), see below | same |

**Project file search.** Inside a Bazel workspace, bz looks for `.bz.toml` in the
current directory and in each parent directory up to the workspace root. The root
is the innermost directory with a `MODULE.bazel`, `REPO.bazel`, `WORKSPACE.bazel` or
`WORKSPACE` file that you or root own, so a nested `MODULE.bazel` ends the search.
The nearest file wins, and project files do not merge with each other. Outside a
workspace, bz only checks the current directory. Your home directory and its
ancestors are never a workspace root. `.bzconfig.toml` is accepted for
compatibility with earlier releases. If one directory has both `.bz.toml` and
`.bzconfig.toml`, bz stops with an error.

**Trust.** bz only reads config files nobody else could have changed:
- A project file must be owned by you or root and not writable by group or others.
- Its directory must be owned by you or root and not writable by group or others (a sticky directory holding your own file is fine).
- The system file must be owned by root.
- The user file must be owned by you or root.

An untrusted file stops the command. See
[Project Config and Trust](/bz/configuration/project-config/) for the full
rules, the common refusals and their fixes, and `BZ_TRUSTED_CONFIG_DIRS`.

Settings in later layers override earlier ones; see
[Configuration Precedence](#configuration-precedence).

<Aside type="caution">
Unknown keys or tables, such as `registery` or `[comands]`, do not stop bz: it
prints a `Warning:` line on stderr naming the file and key, and ignores the key.
A malformed file, an invalid value, an untrusted file or a problem locating the
project file stops the command before it runs, with one `Error:` line that names
the file or variable. Invalid values include an unknown `mode`, a `timeout` or
`ttl` that is not a Go duration (`"30s"`, `"24h"`), a `registry` or
`fallback_registries` entry that is not an `https://`, `http://` or `file://`
URL or an absolute path, and an unparsable `BZ_OFFLINE`. The command does not
run, so a typo can never quietly drop the rest of the file, such as
`[commands] disabled`. `help`, `version` and `completion` still run with a
broken file and show the error as a warning.
</Aside>

## Full Example

```toml
# ~/.config/bz/config.toml

# Network settings
[network]
mode = "prefer-offline"           # "online", "prefer-offline", or "offline"
registry = "https://bcr.bazel.build"
fallback_registries = [
    "https://mirror.internal.com/bcr",
]
timeout = "30s"

# Cache settings
[cache]
dir = "~/.cache/bz"               # Cache directory ("~" is expanded)
ttl = "24h"                       # Cache time-to-live (accepted, not yet applied)

# Command settings
[commands]
disabled = ["audit"]              # Disable specific commands
```

## Configuration Sections

### `[network]`

Controls how bz accesses registries.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `mode` | string | `"online"` | Network mode: `online`, `prefer-offline`, or `offline` |
| `registry` | string | `"https://bcr.bazel.build"` | Primary registry URL. Used by `mod`, `cache download`, `registry ping`, `sbom`, `doctor` and the TUI |
| `fallback_registries` | array | `[]` | Backup registries to try if the primary fails. Validated and loaded, but not yet used by any command |
| `timeout` | string | `"30s"` | Request timeout (Go duration such as `"30s"` or `"2m"`; must be positive). Validated and loaded, but HTTP clients still use their built-in timeouts |

**Network modes:**

| Mode | Behavior |
|------|----------|
| `online` | Always fetch from network (default) |
| `prefer-offline` | Use cache if available, fallback to network |
| `offline` | Never access network, fail if not cached |

```toml
[network]
mode = "offline"
registry = "file:///opt/bazel-registry"
```

### `[cache]`

Controls the local module cache.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `dir` | string | see below | Cache directory path. A leading `~` is expanded. A relative path is resolved against the directory of the file that sets it |
| `ttl` | string | `""` | Cache entry time-to-live (empty = never expire). Values are Go durations using `h`, `m` and `s` (for example `"168h"` for a week); `"7d"` is not accepted. Validated but not yet applied |

```toml
[cache]
dir = "/var/cache/bz"
```

**Cache directory resolution** (first match wins):

1. The command's `--cache-dir` flag (`bz cache download|stats|verify|clear`)
2. `BZ_CACHE_DIR`
3. `[cache] dir` from the highest config layer that sets it
4. The built-in default:
   - `~/.cache/bz` if that directory already exists. Earlier releases always
     used this path, so an existing cache is never orphaned.
   - otherwise `$XDG_CACHE_HOME/bz` when `XDG_CACHE_HOME` is set to an absolute path
   - otherwise `%LocalAppData%\bz\cache` on Windows and `~/.cache/bz` elsewhere

### `[commands]`

Controls command availability.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `disabled` | array | `[]` | Commands to disable |

```toml
[commands]
disabled = ["audit", "sbom"]
```

<Aside type="caution">
Disabled commands will return an error when invoked. This is useful for restricted environments where certain commands should not be available.
</Aside>

## Environment Variables

This is the complete list of variables that affect configuration:

| Variable | Equivalent config | Description |
|----------|-------------------|-------------|
| `BZ_OFFLINE` | `network.mode = "offline"` | Enable offline mode |
| `BZ_PREFER_OFFLINE` | `network.mode = "prefer-offline"` | Enable prefer-offline mode |
| `BZ_REGISTRY` | `network.registry` | Override registry URL |
| `BZ_CACHE_DIR` | `cache.dir` | Override cache directory (`~` is expanded) |
| `BZ_DISABLE_COMMANDS` | `commands.disabled` | Disable commands (comma-separated) |
| `BZ_TRUSTED_CONFIG_DIRS` | | Directories whose config files skip the ownership and permission checks, separated like `PATH`. See [Project Config and Trust](/bz/configuration/project-config/#trusting-a-directory) |
| `XDG_CONFIG_HOME` | | Where to look for the user config file (absolute paths only) |
| `XDG_CACHE_HOME` | | Base directory for the default cache directory, used only when `~/.cache/bz` does not already exist |
| `NO_COLOR` | | Disable colored output (same as `--no-color`) |

This is the complete list of variables that affect configuration.

**Boolean values:** `BZ_OFFLINE` and `BZ_PREFER_OFFLINE` accept `1`, `true`, `yes`
or `on` for true and `0`, `false`, `no`, `off` or an empty value for false
(case-insensitive). Any other value is an error that stops the command.

A false value does not switch a config file's `mode = "offline"` back to online.
To do that, set `mode = "online"` in a higher config layer. If both variables are true,
`BZ_OFFLINE` wins. Empty `BZ_REGISTRY`, `BZ_CACHE_DIR` and `BZ_DISABLE_COMMANDS`
count as unset; surrounding spaces in `BZ_REGISTRY` and `BZ_CACHE_DIR` are ignored.
`BZ_DISABLE_COMMANDS=","` replaces the list from the config files with an empty
list, re-enabling every command. `BZ_REGISTRY` is validated like `registry`.

```bash
# Enable offline mode
export BZ_OFFLINE=1

# Use custom registry
export BZ_REGISTRY="https://internal.registry.com"

# Disable specific commands
export BZ_DISABLE_COMMANDS="audit,sbom"
```

## Configuration Precedence

Configuration is merged in this order (later overrides earlier):

| # | Layer | Where |
|---|-------|-------|
| 1 | Built-in defaults | |
| 2 | System config | `/etc/bz/config.toml` (Windows: `%ProgramData%\bz\config.toml`) |
| 3 | User config | `~/.config/bz/config.toml` or `$XDG_CONFIG_HOME/bz/config.toml` (Windows: `%AppData%\bz\config.toml`) |
| 4 | Project config | `.bz.toml` or `.bzconfig.toml`, nearest from the current directory up to the workspace root |
| 5 | Environment variables | see above |
| 6 | Command-line flags | `--offline`, `--prefer-offline`, `--registry` (and `mod --registry`, `cache download --registry`, `cache * --cache-dir`) |

Each layer overrides only the keys it sets. A project file that sets only `[cache] dir`
keeps the user file's `mode = "offline"`. A higher layer can also set a key back to
its default. For example, `mode = "online"` or `registry = "https://bcr.bazel.build"` in a project file
overrides a user file's offline mode or mirror. Lists such as `disabled` and
`fallback_registries` are replaced, not merged. The system file provides defaults
that higher layers can override; it is not a lock.

`--offline` and `--prefer-offline` cannot be combined. Either flag overrides the
mode from config files and the environment. With `mode = "offline"` in a config file,
`bz --prefer-offline ...` runs in prefer-offline mode, and with
`mode = "prefer-offline"`, `bz --offline ...` runs offline.

## Common Configurations

### Air-gapped Environment

For machines without internet access:

```toml
# /etc/bz/config.toml (system-wide)

[network]
mode = "offline"
registry = "file:///opt/bazel/registry"

[cache]
dir = "/opt/bazel/cache"

[commands]
disabled = ["registry ping"]  # No point in pinging
```

### CI/CD Pipeline

For build servers:

```toml
# .bz.toml (project config)

[network]
mode = "prefer-offline"
registry = "https://internal-mirror.company.com/bcr"
timeout = "60s"

[cache]
dir = "/tmp/bz-cache"
```

Or via environment variables in your CI config:

```yaml
# .github/workflows/build.yml
env:
  BZ_PREFER_OFFLINE: "1"
  BZ_REGISTRY: "https://internal-mirror.company.com/bcr"
  BZ_CACHE_DIR: "/tmp/bz-cache"
```

### Development Machine

For developers who want fast local builds:

```toml
# ~/.config/bz/config.toml

[network]
mode = "prefer-offline"

[cache]
dir = "~/.cache/bz"
```

### Restricted Environment

For security-sensitive environments:

```toml
# /etc/bz/config.toml

[network]
mode = "offline"
registry = "file:///approved/registry"

[commands]
disabled = ["audit"]  # Disable commands that require network
```

## Validating Configuration

bz has no `config show` command yet. To check what is in effect:

```bash
# Unknown keys and invalid values are reported on every run
bz version

# Shows which registry is being used (from config, BZ_REGISTRY or --registry)
bz registry ping

# Checks the configured registry, or reports that offline mode skips the check
bz doctor
```

Error messages that depend on configuration name the layer that set the value,
for example `Offline mode is set by user config /home/me/.config/bz/config.toml.`

## Registry URL Formats

The `registry` setting accepts several URL formats:

| Format | Example | Description |
|--------|---------|-------------|
| HTTPS | `https://bcr.bazel.build` | Standard BCR-compatible HTTP registry |
| HTTP | `http://internal:8080` | Unsecured HTTP (local/internal only) |
| File | `file:///path/to/registry` | Local filesystem registry |
| Path | `/path/to/registry` | Shorthand for file:// |

```toml
[network]
# Standard BCR
registry = "https://bcr.bazel.build"

# Internal mirror
registry = "https://mirror.internal.company.com/bcr"

# Local filesystem
registry = "file:///opt/bazel/registry"
# or
registry = "/opt/bazel/registry"
```
